# Стабилизация планирования и завершения исследования (Test1)

## Что было не так

В сохранённом Test1 планирование остановилось после четырёх ревизий. Более
ранний вариант из семи задач имел замечания по полноте, но последний вариант
из девяти задач превысил лимит восемь. Последний черновик вытеснил полезный
кандидат; расчёты не начались. При этом нормальный возврат AgentTool и
завершение корутины были приняты внешним контроллером за завершение исследования.
В корневом плане остались TASK-1 и TASK-3.

## Новые правила

### Границы и размер плана

Литература выполняется ResearchAgent у оркестратора, а не внутри модуля
экспериментов. Вычислительная проекция сохраняет исходные идентификаторы
операций; литературные операции остаются обязательствами родительского плана.
Подробнее: [граница литературы](experiment_literature_boundary.md).

У задачи один `design.operation_ref`, поэтому N обязательных операций требуют
как минимум N задач. До вызова планировщика `experiments/plan_policy.py`
согласует превышение настроенного лимита. Человек может разрешить больший лимит
только для текущего experiment_run_id и точного набора операций, не более 20
задач. Это не повышает общий бюджет обращений к моделям. Автоматический режим,
отказ и таймаут не являются согласием. Более 20 операций требуют разделения
объёма на этапы; список не обрезается.

`context.plan_limits` — единый источник ограничений для промпта и проверок.
Глобальные настройки не меняются. Смена запуска или операций отменяет действие
разрешения на повышенный лимит.

### Сохранение и согласование выполнимого варианта

`experiments/review.py` хранит два разных checkpoint:

- `experiment_plan_last_schema_valid_candidate` — последний структурно
  корректный черновик и его диагностику;
- `experiment_plan_last_executable_candidate` — последний выполнимый вариант.

При исчерпании ревизий сначала проверяется текущий вариант, затем сохранённый
выполнимый. Непокрытые операции и замечания показываются человеку, а не
исчезают из задания. Согласие относится к точному digest плана. Проверка
актуальных инструментов, маршрутов и ограничений повторяется до и после
согласования. Невыполнимый маршрут нельзя сделать исполнимым одобрением.

Явное продолжение открывает согласование сохранённого кандидата без нового
вызова планировщика или критика и без сброса ревизий. Уже одобренный runtime
и полученные результаты защищены от запоздавшего ответа старого планировщика.
Отказ и повторная неудача оставляют диагностируемую паузу, не цикл регенерации.

### Совместимость данных — на уровне задачи

Реестр и поиск передают `input_schema`, `output_schema` и необязательный
`data_contract = {input_mode, dataset_scope}`. Метаданные проходят через
retrieval, накопленный inventory, контекст планировщика и runtime.

- Инструмент с явно объявленным `fixed_dataset` может работать без внешнего
  CSV, если его набор данных соответствует задаче.
- Явное несовпадение фиксированного набора блокирует только соответствующий
  маршрут задачи до внешнего вызова и допускает ограниченный fallback, в том
  числе к Coder. Независимые задачи остаются доступными.
- У `caller_data` корпус обучения сам по себе не запрещает обработку новых
  входных данных. Обязательные аргументы проверяются перед вызовом инструмента.
- Неизвестные метаданные не означают доказанную несовместимость. Имя инструмента
  или отсутствие аргументов не доказывают, с какими данными он работает.
- GeneratedData с реальной ссылкой доступен как вход, но не становится
  проверенным автоматически. Текст литературы и DOI не превращаются в CSV.

Для строгой проверки старых MCP нужно заполнить декларации в реестре или
`input_schema.x-data-contract`; код не выдумывает их по именам серверов.

### Правдивое завершение и продолжение

`experiments/outcome/reconciliation.py` сопоставляет результаты review,
runtime, выбранные этапы и корневые задачи. Его используют web-контроллер,
отметки этапов и защита финального отчёта. Сам текст агента, файл или обычный
возврат функции не означают завершение.

Различаются завершение, отрицательный научный результат, завершение с
ограничениями и пауза. Неподтверждённая гипотеза не требует автоматического
повтора. Принятие результатов эксперимента не закрывает прочие задачи
исследования. Нельзя принять ограниченный итог, пока экспериментальные задачи
ещё выполняются.

На паузе доступны отдельные явные действия: согласовать сохранённый план,
разрешить допустимый размер плана, продолжить оставшиеся корневые задачи или
принять неполный итог с перечислением конкретных незавершённых пунктов.
Последнее согласие привязано к controller run_id и digest дорожной карты,
не превращает TODO в DONE и не переносится на новый запуск. Повтор команды
идемпотентен; независимые причины паузы, включая бюджет, сохраняются.

Web использует последнее состояние ADK после возврата исследования, сохраняет
его для продолжения и не рассылает преждевременное финальное завершение.
Отказ в повторном вызове модуля также не сохраняет ложное обещание модели
«сейчас перезапущу».

## Развёртывание и границы гарантии

Нужен перезапуск приложения/пересборка дерева агентов для загрузки кода и
конфига. Изменения не перезапускают исследования автоматически и не делают
старые completed-сессии продолжаемыми задним числом.

Проверка сохранённого состояния Test1 новым reconciler даёт `paused`,
`max_plan_revisions`, TASK-1/TASK-3 незавершены, финальный отчёт запрещён.
Но в самом старом snapshot нет нового executable checkpoint: сохранён только
заблокированный девятизадачный кандидат. Утраченный промежуточный план нельзя
восстановить из отсутствующих данных; для реального продолжения нужен отдельный
контролируемый запуск/восстановление из подходящего checkpoint.

Регрессионные тесты выполняются без платных расчётов. Они проверяют переходы и
контракты, но не гарантируют стоимость, научную достоверность или доступность
внешних MCP/Coder. Перед рабочим использованием следует прогнать копию кейса
после перезапуска, сохранив исходную сессию.

Итог проверки реализации 2026-09-27: **571 passed** в объединённом прогоне
`tests/unit/experiment` и тестов pipeline scope, configuration policy,
report guard, web run control, execution control/model gates/CLI, plugin errors,
FEDOT budget и UI счётчика/таймера. Проверка `git diff --check` изменённых
отслеживаемых файлов пройдена. Реальные исследования, обучение, докинг и
перезапуск рабочего сервера в эту проверку не входили.
