# Каталог MCP-инструментов в Web: архитектура и план

Статус: реализовано в рабочей ветке. Страница: `/tools`, API:
`GET /api/mcp-tools`, ручное обновление: `POST /api/mcp-tools/refresh`.
Основание: чтение текущей ветки `dev_1`, PostgreSQL Tool RAG и проверка
`initialize` + `tools/list` подключённых MCP-серверов 26 сентября 2026 года.
При проверке бизнес-инструменты не вызывались.

## Что обнаружено

- В текущем реестре Tool RAG: 11 серверов и 87 записей инструментов.
- После добавления подключений из настроек: 14 различных проверенных адресов.
  Подключение paper-analysis совпало с записью dataset-collection и учитывалось
  один раз. Остальные дополнительные подключения: поиск статей, нормоконтроль,
  Tavily.
- На MCP discovery ответили 10 адресов, суммарно вернувших 68 инструментов.
  Это подтверждение доступности описаний, а не успешного выполнения всех
  научных операций. Числа относятся к моменту проверки из этой рабочей среды.
- AutoMLTools, epid-forecasting-mcp-local, demo и нормоконтроль вернули
  ConnectError. Их доступность в другом окружении может отличаться.
- Реестр и фактические серверы расходятся. Например, запись
  hybrid-surrogate-epidemics содержит 13 инструментов эпидемического
  моделирования, но её адрес сейчас возвращает 3 инструмента OpenAlex.
  dataset-collection содержит 2 индексированных инструмента, а фактически
  возвращает 5 инструментов работы с научной литературой.
- Есть одинаковые имена на разных серверах: reproduce_all, reproduce_claims,
  get_mcp_logs. Объединять инструменты только по имени нельзя.
- `mcp_tools.csv` — исторический снимок. В частности, его AutoML-описания и
  статус отличаются от текущего PostgreSQL. Источником актуального каталога
  этот файл быть не должен.

### FEDOT

Нужный сервер — AutoMLTools, текущий registry ID `d6dac6fb09066080`.
В актуальном индексе 8 инструментов:

- train_ml;
- predict_ml;
- train_ml_job_status;
- check_state;
- list_automl_train_cases;
- get_s3_train_case_columns;
- health_check;
- get_mcp_logs.

Связь с FEDOT подтверждается описанием `train_ml.timeout`: бюджет поиска
передаётся FEDOT в минутах. Это отдельный MCP-сервис, не агент FEDOT.MAS.

`train_ml` принимает подготовленный датасет по URL, имя задачи и списки
целевых свойств для регрессии/классификации; обучение фоновое, результат
запуска — job_id. Одного target_column недостаточно: требуется хотя бы один
из regression_props/classification_props. `predict_ml` использует ранее
обученную модель и принимает SMILES либо файл с молекулами.

## Предлагаемый вид страницы

Название в навигации: «Каталог инструментов». Адрес: `/tools`.

Описание под заголовком:

> Подключённые научные инструменты CoScientist: какие задачи они решают,
> откуда доступны и когда их список был обновлён.

Существующий ToolsViewer остаётся представлением инструментов текущей
сессии. Новый каталог относится ко всему развёртыванию CoScientist и
открывается отдельной страницей рядом со «Статистикой статей».

Верхний блок:

1. Число инструментов, обнаруженных при свежей проверке MCP.
2. Число отвечающих серверов / всех настроенных серверов.
3. Число предметных категорий: AutoML, химия, литература, прогнозирование,
   работа с данными и файлами и другие по фактическому каталогу.
4. Число серверов, требующих внимания: недоступность или расхождение с индексом.

Рядом — время последней проверки, индикатор обновления и кнопка
«Обновить сейчас». Отдельная подпись объясняет число записей в индексе и
сколько описаний показано только из сохранённых данных. Эти числа нельзя
складывать с числом живых инструментов.

Далее — поиск по человеческому названию, описанию и техническому имени;
фильтры по категории, серверу, состоянию и назначению
(научные / вспомогательные / служебные). При фильтрации виден счётчик
«Показано N из M». Тип подключения, например HTTP, вынесен в детали сервера.

Каждая карточка содержит понятное название, 1–3 предложения о задаче,
входе и результате, категорию, название сервера и состояние. Раскрытие
«Технические сведения» показывает машинное имя, исходное описание,
параметры и источник/время получения метаданных. Секреты и служебные
адреса подключения в клиентский ответ не передаются.

### Первая карточка

**Инструменты автоматического машинного обучения для научных задач — FEDOT**

> Обучение моделей на подготовленных данных о молекулах и предсказание
> свойств новых молекул по их структуре. Сервис запускает обучение,
> позволяет отслеживать его состояние и применять ранее обученные модели.

Первые две операции внутри блока:

- «Обучить модель для предсказания свойств молекул» — train_ml.
  По таблице молекул и измеренных свойств запускает автоматический подбор
  и обучение модели. Возвращает идентификатор для проверки хода обучения.
- «Предсказать свойства молекул» — predict_ml.
  Применяет ранее обученную модель к списку молекул или файлу с их
  структурами и возвращает прогнозы выбранных свойств.

Остальные операции AutoMLTools доступны в раскрываемом списке. Закрепление
определяется явным metadata key/registry ID, а не совпадением слова FEDOT
в произвольном описании. Первая позиция сохраняется при временной
недоступности; карточка показывает «Нет соединения, сохранённое описание»
и время последней успешной проверки. При поиске/фильтрации карточка, как
и остальные, должна соответствовать запросу.

## Архитектура

### 1. Полный список источников

Новый сервис `CoScientist/tools/mcp_catalog.py` получает:

- Полный перечень servers/tools из PostgreSQL, используемого Tool RAG.
  `retrieve_tools` здесь не подходит: это поиск top-k, требующий query,
  embeddings/reranking, а не перечисление всех подключений.
- MCP-подключения из эффективных настроек: paper_analysis, papers_search,
  vault, normcontrol и Tavily. Остальные MCP-поля включаются только если
  реально используются адаптерами системы. Произвольные URL из env,
  базы данных, S3, Opik и обычные REST-сервисы MCP-серверами не считаются.

Небольшой общий resolver MCP-подключений переиспользуется каталогом и
существующими MCP-клиентами: одинаковые URL, headers, правила proxy и
tool_filter. Проверка учитывает optional flags и доступность для агентов,
отдельно от наличия описания на сервере. FEDOT.MAS и локальные Python tools
не входят в счётчик MCP-инструментов.

Настройки читаются из того же `get_settings`, что использует приложение.
Изменение env при запущенном процессе подчиняется обычному механизму
перезагрузки приложения: страница не должна обещать мгновенное применение
правки `.env`, пока runtime продолжает использовать старые настройки.

Доступ к реестру — SELECT в read-only транзакции через небольшой адаптер.
Не использовать текущий `PostgresClient.initialize()` для Web-запроса:
он вызывает create_all и может создавать таблицы. Не вызывать регистрацию,
индексацию или синхронизацию Tool RAG ради открытия страницы.

### 2. Проверка живых метаданных

Для подключённых HTTP MCP: initialize, затем tools/list с обработкой всех
nextCursor. Одна сессия на сервер, ограниченная параллельность (например,
4 сервера), отдельный дедлайн (15 секунд) и общий дедлайн обновления.
Сессии закрываются и при успехе, и при отмене/ошибке. Бизнес-инструменты,
в том числе health_check, train_ml и predict_ml, для каталога не вызываются.

В текущем реестре все подключения HTTP. Иные транспорты, если появятся,
отражаются явно; запуск произвольной stdio-команды в HTTP-обработчике
не добавляется в первую версию.

Успешный tools/list определяет текущий список данного сервера. При сбое
отображается последний успешный снимок либо записи индекса, помеченные
как сохранённые/непроверенные. Исчезнувшие инструменты не остаются
«доступными» после успешного нового листинга.

При несовпадении индексного и живого списка сохраняются оба источника
с признаком расхождения. Исторические записи выводятся в отдельном
раскрытии и не входят в счётчик актуальных инструментов. serverInfo из
initialize помогает обнаружить подменившийся сервис; изменение состава
инструментов само по себе не доказывает подмену. Каталог не исправляет
Tool RAG автоматически.

### 3. Идентичность и ответ API

Основной ключ инструмента: логический сервер + точное tool_name.
Реестр использует server_id; env-подключение получает стабильный ключ.
Совпадение env-подключения и registry-записи объединяется по нормализованному
endpoint и контексту доступа, сохраняя алиасы/источники. Не объединять
разные серверы из-за одинаковых названий функций; учитывать различие
авторизации для одинакового URL. URL и auth fingerprint — внутренние поля.

Ответ включает:

- snapshot_id, checked_at, last_success_at, refreshing, partial, stale;
- независимое состояние registry-источника и каждой MCP-проверки;
- servers: id, display_name, sources, registry_status, discovery_status,
  checked_at, last_success_at, tool_counts, discrepancy;
- tools: id, server_id, name, display_name, summary, category, role,
  input/output schema, original_description, metadata_source,
  metadata_hash, presentation_status, available_to_agents;
- summary с раздельными живыми и сохранёнными счётчиками.

Пустая JSON schema отображается как «Параметры не описаны», а не как
«Параметры отсутствуют». Успешный листинг и возможность вызова конкретным
агентом — отдельные признаки: существуют tool_filter и системные операции.

### 4. Обновление и хранение

`GET /api/mcp-tools` немедленно отдаёт снимок, без сетевого обхода на каждый
браузерный запрос. `POST /api/mcp-tools/refresh` запускает или присоединяет
к уже идущему обновлению; повторные нажатия не создают новые обходы.
Оба пути используют обычные правила доступа существующего Web-приложения.
Клиент не передаёт произвольные адреса для опроса.

Снимок хранится в памяти и атомарно на диске под WEB_STATE_DIR. Сохраняются
только публичные метаданные, без URL с ключами, env и headers. После
перезапуска он сразу доступен с указанием возраста. Если отключено
подключение, старый снимок не возвращает его в активный список.

Предложенные значения первой версии:

- обновление discovery раз в 5 минут при использовании страницы;
- запрос состояния браузером раз в 30 секунд, чаще во время обновления;
- при открытии/возвращении на вкладку — проверка свежести;
- ручное обновление запускает discovery немедленно;
- скрытая вкладка не инициирует регулярные обновления;
- ошибка одного сервера не очищает весь каталог.

Single-flight защищает один процесс, межпроцессная блокировка/lease
защищает общий WEB_STATE_DIR от параллельных refresher нескольких workers.
При разных файловых системах каждый экземпляр имеет свой снимок: для
общего снимка всего кластера потребуется общее хранилище и lease.

### 5. Человеческие названия и описания

Новый небольшой `CoScientist/config/tool_catalog.yaml` содержит только
presentation metadata: RU/EN title, summary, category, role, priority,
стабильную привязку к серверу/инструменту и hash исходного описания.
Он не дублирует подключения, auth или схемы инструментов.

Начальный набор описаний готовится для фактически обнаруженных и
сохранённых инструментов; известные ToolDoc можно использовать как
дополнительный материал. Изменение исходного описания/схемы инвалидирует
подтверждённый текст, чтобы старый перевод не описывал другую операцию.

Новые инструменты появляются сразу. Для них машинное имя безопасно
преобразуется в читаемый заголовок, а карточка получает краткую первую часть
исходного описания. Полное описание и схема остаются в техническом раскрытии.
Проверенные RU/EN тексты из YAML имеют приоритет. Автоматический перевод через
LLM намеренно не запускается при открытии или обновлении страницы: discovery
остаётся быстрым, предсказуемым и не расходует модельные вызовы.

Показ страницы и discovery не зависят от доступности модели. Текст
рендерится безопасно как данные; встроенные инструкции из удалённых
описаний не исполняются, HTML не вставляется без обработки. Для FEDOT
используется проверенный вручную текст выше.

## План реализации

1. Реализован read-only адаптер реестра и resolver подключённых MCP.
2. Реализованы bounded discovery, pagination, объединение источников и
   вычисление расхождений.
3. Добавлены атомарные снимки, single-flight refresh, межпроцессный lease,
   восстановление после перезапуска и Web API.
4. Добавлен presentation YAML с RU/EN описанием и приоритетом AutoMLTools,
   train_ml и predict_ml.
5. Добавлены templates/tools.html, отдельные JS/CSS, статистика, карточки,
   фильтры, раскрытия, обновление, навигация и i18n.
6. Добавлены тематические тесты; выполнена ручная проверка с текущими
   MCP-серверами, включая недоступный AutoML и расхождение OpenAlex.

## Критерии приёмки

- Каталог включает реестр и env-подключения; отключённые/недоступные записи
  не выдаются за проверенные работающие инструменты.
- Одинаковые имена на разных серверах остаются разными инструментами;
  одно подключение из env и реестра не удваивает счётчики.
- Все страницы tools/list учтены; сломанная пагинация/таймаут ограничены.
- Успешное обновление убирает исчезнувшие инструменты из текущего списка;
  временный сбой сохраняет последний успешный снимок и его время.
- При недоступной БД доступны настроенные напрямую серверы; при сбое
  сервера остальные данные сохраняются. Частичный результат явно отмечен.
- Одновременные refresh не создают лавину соединений; перезапуск не
  обнуляет сохранённый каталог. Конфигурационные изменения инвалидируют
  неподходящие старые подключения/снимки.
- Карточка FEDOT стоит первой при стандартной сортировке и содержит точную
  фразу «автоматического машинного обучения для научных задач».
- Названия/описания понятны пользователю; исходный контракт доступен в
  деталях. Изменившийся контракт не наследует неподходящий старый перевод.
- Страница не запускает обучение, расчёты, поиск статей или регистрацию
  серверов. В API/HTML/кеше отсутствуют auth headers, ключи и секретные URL.
- Поведенческие UI-проверки покрывают фильтры, пересчёт статистики, refresh,
  частичный сбой, сохранение раскрытий и RU/EN. Тематические Python-тесты
  проверяют discovery, источники, идентичность, snapshots и API.

## Опорные места в коде

- CoScientist/tools/retrieval_tools.py: retrieve_tools и восстановление
  метаданных из PostgreSQL.
- CoScientist/tools/research_tools.py: прямые подключения, headers, proxy,
  tool_filter хранилища артефактов.
- CoScientist/config/settings.py: MCPSettings, ToolRAGSettings, ServicesSettings.
- CoScientist/web/templates/stats.html и web/app.py: визуальная структура
  статистики статей и существующие маршруты.
- CoScientist/tools/paper_statistics_client.py: изолированная MCP-сессия
  с таймаутом, без агентного запуска.
- CoScientist/web/session_store.py: WEB_STATE_DIR, атомарная запись снимков.
- CoScientist/web/static/js/activity_rail.js и i18n.js: навигация и подписи.
- CoScientist/assembly/bindings.py: ToolDoc для известных инструментов.
