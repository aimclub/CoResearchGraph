# Управляемое выполнение исследований

## Что ограничено

Один пользовательский запуск получает не более 100 попыток обращения к моделям,
которыми управляет этот процесс CoScientist. Счётчик общий для оркестратора,
вложенных агентов, критиков, прямых вызовов и локально запускаемого FEDOT.MAS.
Каждая транспортная попытка, в том числе неудачная, учитывается перед отправкой.
Встроенные повторы SDK отключены; управляемый повтор требует новой резервации.

Это **не лимит токенов, долларов или всех вызовов инструментов**. Внутренние
обращения непрозрачных удалённых Coder/OpenHands и других внешних сервисов сюда
не входят. Отдельный дорогостоящий запрос также может расходовать много токенов.
Интерфейс явно обозначает границу счётчика.

После исчерпания система ждёт решения: ещё 100 обращений или остановка.
Автоматический режим, пауза, повтор подключения, перепланирование и перезапуск
сервера не дают новый бюджет. Повтор одной команды продления идемпотентен.
Старые настройки `ORCHESTRATOR__MAX_LLM_CALLS > 100` ограничиваются значением 100.

## Завершение и качество — разные вещи

У результата есть `execution_status` (завершено, с ограничениями, ошибка,
пропущено) и `assessment_status` (критерий достигнут, не достигнут, неясно,
не оценивался). Низкая метрика или неподтверждённая гипотеза не запускают
автоматическое перепланирование.

Критерии `purpose=execution` проверяют оговорённую поставку результата:
например, завершение расчёта и пригодность требуемых данных/схемы.
Критерии `purpose=assessment` оценивают научный результат. Диагностический файл,
лог ошибки или произвольный путь сам по себе не подтверждает выполнение.
Честная ошибка тоже фиксируется как результат попытки, с причиной и ограничениями.

Автоматическое техническое восстановление ограничено тремя попытками на
логическую операцию суммарно по маршрутам (по одному маршруту — не более двух).
Косметическое переименование задачи, смена маршрута, пауза и новая версия плана
не обнуляют историю. Независимые задачи могут продолжаться; задачи с отсутствующими
входами не выдаются за успешно выполненные.

## Выход из тупика

Один детерминированный селектор управляющих действий учитывает активную попытку,
фазу, `state_revision` и `next_actions`. Он не заставляет одновременно делать
`record_result`, fallback и чтение плана. Ошибочный ответ инструмента содержит
диагностику и допустимые следующие действия. Несовпадение входного контракта
инструмента позволяет перейти к маршруту изменения кода; диагностический
артефакт не блокирует Coder как якобы готовое доказательство.

Три одинаковых управляющих сбоя или пять управляющих действий без изменения
состояния вызывают настоящую паузу до новых обращений к модели. Пользователь
может явно завершить оставшиеся задачи с ограничениями и перейти к оценке.
Такая команда сохраняет успешные результаты и не создаёт вымышленных успехов.
Она не отменяет уже выполняющиеся внешние процессы.

На этапе оценки можно принять результат вместе с замечаниями либо явно выбрать
задачи для новой версии. UI показывает зависимые задачи, которые тоже будут
пересчитаны. Требуется описание изменения. Старые результаты сохраняются,
независимые успешные задачи не переисполняются. Новая явная версия получает
конечный лимит технических попыток, но **не новый общий бюджет LLM**.

## Пауза и восстановление

Пауза кооперативная: текущий запрос или внешний процесс может завершиться,
но новые модельные/инструментальные действия ждут. Продолжение в работающем
сервере снимает причину паузы в той же корутине, не запускает исследование с нуля.
Причины независимы: ручная пауза, бюджет и ожидаемое согласование не снимают друг
друга. Таймаут ожидания человека не считается его согласием и не блокирует форму.

SQLite хранит бюджет, причины пауз, решения оператора, последнее безопасное
состояние и журнал отправки/завершения инструментов. Файл расположен в
`WEB_STATE_DIR/execution_control.sqlite3`; путь можно задать через
`COSCIENTIST_EXECUTION_DB`. Каталог должен быть постоянным томом контейнера.

После перезапуска сервера продолжение требует явной команды. Сохраняются номера
задачи/попытки, результаты, счётчик и стадия. Завершённые внешние действия при
точном совпадении операции читаются из журнала, а не отправляются повторно.
Если отправка была записана, но исход неизвестен, восстановление останавливается
для проверки внешнего задания. После проверки оператор может явно разрешить
повтор с пояснением и отдельно нажать «Продолжить»; это не сбрасывает бюджет.
Работающий внешний процесс повторять нельзя. Невозможность сериализовать
исполняемое состояние не скрывается преобразованием всего состояния в строки.

Это механизм продолжения, а не прежний откат checkpoint. Старые `.cossession`
без журнала нового контроллера не приобретают гарантий безопасного повтора задним
числом. Гарантия exactly-once для сторонних сервисов без их поддержки
идемпотентности не заявляется; неоднозначные исходы требуют проверки человеком.

## Связь с реализацией

| Область | Файлы |
| --- | --- |
| Общий бюджет и журнал | `CoScientist/execution_control/` |
| Границы паузы и безопасное продолжение | `agents/run_control_plugin.py` |
| Web-команды, восстановление | `web/run_control.py`, `web/app.py` |
| CLI-решение о дополнительном бюджете | `execution_cli.py` |
| Контракты, попытки, версии результатов | `experiments/runtime/state_machine.py`, `reporting/models.py` |
| Маршруты, единый селектор, остановка тупика | `runtime/guards.py`, `agents/loop_guard_plugin.py`, `agents/callbacks/tool_callbacks.py` |
| Согласование и точечный повтор | `experiments/review.py`, `web/handler.py`, `web/static/js/hitl.js` |
| Пауза и счётчик в UI | `web/static/js/run_control.js`, `static/status_indicator.js` |

HTTP-команды находятся под
`/api/users/{user_id}/sessions/{session_id}/runs/{run_id}`:
`pause`, `resume`, `budget/decision`, `recovery/authorize-retry`,
`recovery/finish-with-limits`. Команды проверяют принадлежность запуска сессии;
`expected_revision` защищает от устаревшего состояния интерфейса.

## Проверка перед развёртыванием

Регрессии покрывают общий/конкурентный бюджет, повтор решения, паузы, reconnect,
восстановление без сброса попытки, неопределённые внешние действия, контракты
результатов, отрицательные метрики, лимит попыток, diagnostic-only → Coder,
идемпотентный `record_result`, точечный повтор и сохранение ввода в UI.

После перезапуска приложения нужна контролируемая проверка на копии демосессии.
Офлайн-тесты используют заглушки: они не доказывают точную стоимость следующего
реального исследования и не требуют платных вызовов или повторного обучения.
