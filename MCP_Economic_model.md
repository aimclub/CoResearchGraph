# chemquote — руководство по работе с сервисом

> Для тех, кто **пользуется** сервисом, а не разрабатывает его. Кодовая база не нужна: здесь описано,
> что сервис умеет, как к нему подключиться, что он возвращает и как это читать.
>
> Устройство изнутри — в [`architecture.md`](./architecture.md).
>
> Актуально для **chemquote 1.28.0** (проверено на живом сервисе 2026-09-17). По сравнению с
> первой версией руководства: добавлен инструмент `resolve_chemicals`; во всех инструментах вещество
> можно задавать **именем**, а не только SMILES; шаги маршрута в `rank_routes_by_cost` принимаются
> объектами с именами и строкой; в ответах появились `resolved_inputs` и `steps_smiles`.

## 1. Что это и когда пригодится

chemquote отвечает на один практический вопрос: **сколько будет стоить купить эти реактивы в России
и у кого дешевле.**

Внутри — сведённые в одну базу прайс-листы российских поставщиков химреактивов. Прайсы приходят в виде
PDF разного формата, на русском языке и **без всякой химической идентификации**: ни SMILES, ни CAS,
ни InChI, только торговые названия вроде «Натрий сернокислый безводный ч.д.а.». Сервис разбирает эти
прайсы, восстанавливает молекулярные структуры по названиям и даёт по ним поиск и расчёт.

Практически это значит, что вы можете:

- искать реактив **по русскому названию**, в том числе с опечаткой;
- искать **по структуре молекулы** — подав SMILES, получить предложения, даже если в прайсе вещество
  названо иначе (синонимом, устаревшей номенклатурой);
- получить **смету** на набор реагентов: сколько это в упаковках и какова себестоимость;
- **сравнить маршруты синтеза** между собой: подать несколько маршрутов реакциями и получить их
  отранжированными по стоимости закупки исходных веществ.

Сервис задуман как узел агентной системы: его вызывает модель или агент, который планирует синтез
и должен обосновать его экономически. Отсюда главный контракт — **вещество задаётся структурой (SMILES)
или именем**, и имя разрешается в структуру до расчёта: считается всегда молекула, а подстановка
возвращается в ответе, чтобы её можно было проверить.

Чего сервис **не** делает: не планирует синтез и не предлагает маршрутов — он оценивает те, что вы
ему дали; не судит о выполнимости реакции и не проверяет её условия; не оформляет заказ, не проверяет
наличие на складе и не пересчитывает валюты по курсу.

## 2. Подключение

Сервис говорит по протоколу **MCP (Model Context Protocol)**, транспорт — streamable HTTP.

```
http://10.32.11.22:8000/mcp
```

Аутентификации нет: эндпоинт доступен внутри лабораторной сети (через VPN). В `.env` CoScientist
это `MCP__ECONOMICS_URL`. Сессия создаётся вызовом
`initialize`, дальше клиент передаёт выданный `mcp-session-id`. Всё это делает за вас любой
MCP-клиент — вручную заголовки собирать не нужно.

**Проверка, что сервис жив:**

```bash
curl -sS -X POST http://10.32.11.22:8000/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{
       "protocolVersion":"2025-03-26","capabilities":{},
       "clientInfo":{"name":"smoke","version":"0"}}}'
```

Ответ приходит событием SSE и содержит `"serverInfo":{"name":"chemquote", ...}`.

**Подключение из Python:**

```python
import anyio
from mcp import ClientSession
from mcp.client.streamable_http import streamablehttp_client

URL = "http://10.32.11.22:8000/mcp"

async def main():
    async with streamablehttp_client(URL) as (read, write, _):
        async with ClientSession(read, write) as session:
            await session.initialize()

            result = await session.call_tool(
                "search_reagents_by_name", {"query": "глицерин", "limit": 5}
            )
            for chunk in result.content:
                print(chunk.text)

anyio.run(main)
```

**Подключение из MCP-клиента (конфигурация):**

```json
{
  "mcpServers": {
    "chemquote": {
      "type": "http",
      "url": "http://10.32.11.22:8000/mcp"
    }
  }
}
```

Все инструменты возвращают **JSON-текст**: один объект на элемент результата. Списочные инструменты
отдают несколько объектов подряд, расчёт — один объект целиком.

## 3. Словарь: предложение, реагент, соединение

Три понятия, которые встречаются в ответах и которые важно не путать.

**Предложение** (`offering`) — одна строка прайс-листа: конкретный товар, конкретная фасовка,
конкретная цена конкретного поставщика. «Ацетон ч, 160 кг, 19 940.28 ₽ у АльфаФТО» — предложение.

**Реагент** — это уже свёртка: все предложения с одним и тем же нормализованным названием.
Поиск по имени возвращает именно реагенты, показывая представителя (самое выгодное предложение)
и число предложений под ним в поле `offer_count`.

**Соединение** (`compound`) — распознанная молекула: канонический SMILES и InChIKey. Соединение
связывает между собой предложения разных поставщиков, названные по-разному. Именно через соединения
работают поиск по структуре и расчёт стоимости.

Ключевой нюанс: **не у каждого предложения есть соединение.** Если название не удалось превратить
в структуру (смесь, технический продукт, стандартный образец, редкое торговое имя), предложение
остаётся в базе и находится по названию, но **невидимо для поиска по SMILES**. Это не ошибка,
а устройство: см. [раздел 12](#12-ограничения-и-подводные-камни).

## 4. Инструмент 1 — `search_reagents_by_name`

**Зачем.** Найти реактив по русскому названию, когда точное написание неизвестно. Устойчив к
опечаткам и к разному порядку слов.

**Параметры:**

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `query` | строка | — | название или его часть |
| `limit` | целое | 20 | максимум реагентов в ответе |

**Возвращает** список реагентов, отсортированный по близости названия к запросу. У каждого —
представитель с наименьшей ценой за единицу.

**Пример:**

```json
{"query": "глицерин", "limit": 3}
```

```json
{
  "name_norm": "глицерин",
  "name_raw": "Глицерин ч",
  "similarity": 1.0,
  "supplier": "АльфаФТО",
  "best_price": "151.87",
  "price_currency": "RUB",
  "pack_qty": "0",
  "pack_unit": "bulk",
  "unit_price": "151.87",
  "purity_grade": "ч.",
  "offer_count": 9
}
{
  "name_norm": "глицерин (имп)",
  "name_raw": "Глицерин (имп)",
  "similarity": 0.6923077,
  "supplier": "Лэнреактив",
  "best_price": "64000.00",
  "price_currency": "RUB",
  "pack_qty": "250",
  "pack_unit": "kg",
  "unit_price": "256.0000",
  "offer_count": 2
}
```

**Опечатки работают:** запрос `ацетн` находит `ацетон`.

**Осторожно — поиск нечёткий.** Он ищет похожие строки, а не одинаковые вещества. По запросу
«глицерин» в выдачу может попасть **«Глицин»** — это другое соединение, у них просто похожие
названия. Если вам нужна именно конкретная молекула, пользуйтесь
[`search_by_structure`](#6-инструмент-3--search_by_structure): он сопоставляет по InChIKey,
а не по буквам.

## 5. Инструмент 2 — `get_price`

**Зачем.** Увидеть **все** предложения по реактиву — все фасовки, всех поставщиков, все квалификации,
отсортированные по цене за единицу. Это инструмент «показать варианты», в отличие от свёрнутого
поиска по имени.

**Параметры:**

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `name` | строка | — | название реактива (нечёткое совпадение) |
| `pack_unit` | строка \| null | null | фильтр по единице фасовки: `g`, `kg`, `ml`, `l`, `pcs`, `vial`, `amp`, `pack`, `set` |
| `purity_grade` | строка \| null | null | фильтр по квалификации: `ч.д.а.`, `х.ч.`, `ос.ч.`, … |
| `limit` | целое | 50 | максимум предложений |

**Пример:**

```json
{"name": "ацетон", "limit": 2}
```

```json
{
  "name_raw": "Ацетон ч",
  "name_norm": "ацетон",
  "supplier": "АльфаФТО",
  "supplier_key": "alfa_ftor",
  "purity_grade": "ч.",
  "pack_qty": "0",
  "pack_unit": "bulk",
  "pack_raw": "н/ф",
  "price": "120.11",
  "price_currency": "RUB",
  "unit_price": "120.11",
  "price_basis": "per_unit",
  "price_basis_suspect": false,
  "gost_tu": null,
  "catalog_no": null,
  "price_list_date": null
}
{
  "name_raw": "Ацетон ч 200л",
  "pack_qty": "160",
  "pack_unit": "kg",
  "pack_raw": "160кг",
  "price": "19940.28",
  "price_currency": "RUB",
  "unit_price": "124.6268",
  "price_basis": "per_package",
  "price_basis_suspect": false
}
```

**Что означают три «ценовых» поля:**

- `price` — то, что напечатано в прайсе.
- `price_basis` — **за что** эта цена: `per_package` (за упаковку) или `per_unit` (за килограмм/литр).
  Разные поставщики печатают по-разному, и это не косметика: перепутав базис, себестоимость можно
  ошибиться в сотни раз.
- `unit_price` — приведённая цена за единицу. Именно по ней имеет смысл сравнивать предложения,
  и именно по ней отсортирован ответ.

Поле `price_basis_suspect: true` означает, что автоматическая проверка сочла базис недостоверным
(например, удельная цена получилась физически невозможной). К такому предложению стоит отнестись
с осторожностью.

Значение `pack_unit: "bulk"` с `pack_qty: "0"` — **навал**: поставщик не указал фасовку («н/ф»).
Цена по такой позиции есть, но посчитать чек нельзя — фактически это «цена по запросу».

## 6. Инструмент 3 — `search_by_structure`

**Зачем.** Найти предложения по **молекуле**, а не по названию. Это надёжный способ: он не зависит
от того, как вещество названо в прайсе — тривиально, по IUPAC или архаично.

**Параметры:**

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `smiles` | строка \| null | null | структура запроса в SMILES |
| `name` | строка \| null | null | имя вещества вместо SMILES («2,6-ди-трет-бутилфенол», «acetyl chloride», «AlCl3») — разрешается в структуру перед поиском. Задавайте **ровно одно** из `smiles` / `name` |
| `mode` | строка | `exact` | `exact` — точное совпадение; `substructure` — молекулы, содержащие фрагмент |
| `limit` | целое | 50 | максимум соединений |
| `use_llm` | булево | `false` | разрешить слой перевода RU→EN моделью для имён, которые не взяли ни словарь, ни правила; медленнее и требует настроенного эндпоинта |

Режим `exact` сначала ищет полное совпадение по InChIKey, а если не нашёл — откатывается на
совпадение **по связности** (без учёта стереохимии и солевой формы). Уровень совпадения всегда
указан в ответе полем `match_level`.

Режим `substructure` находит все молекулы, содержащие поданный фрагмент: `c1ccccc1` вернёт
ароматические соединения с бензольным кольцом.

**Пример:**

```json
{"smiles": "OCC(O)CO", "mode": "exact", "limit": 2}
```

```json
{
  "canonical_smiles": "OCC(O)CO",
  "inchikey": "PEDCQBHIVMGVHV-UHFFFAOYSA-N",
  "display_name_en": null,
  "match_level": "точный",
  "similarity": 1.0,
  "supplier": "НеваРеактив",
  "best_price": "472.00",
  "price_currency": "RUB",
  "pack_qty": "12.000",
  "pack_unit": "kg",
  "unit_price": "472.00",
  "offer_count": 7
}
```

Здесь видно главное преимущество структурного поиска: на входе был SMILES глицерина, а нашлось
предложение, которое в прайсе называется «ГЛИЦЕРИН 99,30%» — сопоставление прошло по молекуле.
Под этим соединением 7 предложений, показано самое выгодное за единицу.

## 7. Инструмент 4 — `resolve_chemicals`

**Зачем.** Превратить имена веществ в структуры — SMILES, InChIKey, формулу, молярную массу — и
увидеть, какой слой это сделал. Вопрос отдельный от сметы: например, чтобы записать маршрут из статьи
в машинном виде, получить молярную массу продукта или надёжный ключ (InChIKey) для сопоставления
вещества между сервисами.

**Параметры:**

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `names` | список строк | — | имена или SMILES, не более 200 за вызов |
| `use_llm` | булево | `false` | разрешить LLM-слой перевода RU→EN для имён, которые не взяли ни словарь, ни правила |

**Каскад разрешения:** словарь русских названий (офлайн) → OPSIN (систематика, офлайн) → PubChem →
NCI/CADD CIR → OPSIN-веб. Русские систематические имена перед этим переводятся на английский по
правилам номенклатуры — PubChem и CIR кириллицу не индексируют. Структура принимается, только если
её разбирает RDKit. Готовый SMILES пропускается насквозь, без обращения к сети.

**Пример:**

```json
{"names": ["бензальдегид", "ацетилхлорид", "AlCl3", "боргидрид натрия", "O=Cc1ccccc1"]}
```

```json
{
  "items": [
    {"input": "бензальдегид", "kind": "name", "canonical_smiles": "O=Cc1ccccc1",
     "inchikey": "HUMNYLRZRPPJDN-UHFFFAOYSA-N", "formula": "C7H6O", "molar_mass": "106.124",
     "method": "ru_iupac", "confidence": 0.85, "translated_from": "benzaldehyde",
     "error": null, "hint": null},
    {"input": "ацетилхлорид", "kind": "name", "canonical_smiles": "CC(=O)Cl",
     "inchikey": "WETWJCDKMRHUPV-UHFFFAOYSA-N", "formula": "C2H3ClO", "molar_mass": "78.498",
     "method": "cas", "confidence": 0.97, "translated_from": null, "error": null, "hint": null},
    {"input": "AlCl3", "kind": "name", "canonical_smiles": "[Cl][Al]([Cl])[Cl]",
     "inchikey": "VSCWAEJMTAWNJL-UHFFFAOYSA-K", "formula": "AlCl3", "molar_mass": "133.341",
     "method": "pubchem", "confidence": 0.88, "translated_from": null, "error": null, "hint": null},
    {"input": "боргидрид натрия", "kind": "name", "canonical_smiles": null, "inchikey": null,
     "formula": null, "molar_mass": null, "method": null, "confidence": null,
     "translated_from": null, "error": "unresolved",
     "hint": "ни словарь, ни OPSIN, ни PubChem/CIR не знают такого имени; помогут английское систематическое имя или готовый SMILES"},
    {"input": "O=Cc1ccccc1", "kind": "smiles", "canonical_smiles": "O=Cc1ccccc1",
     "inchikey": "HUMNYLRZRPPJDN-UHFFFAOYSA-N", "formula": "C7H6O", "molar_mass": "106.124",
     "method": "smiles", "confidence": 1.0, "translated_from": null, "error": null, "hint": null}
  ],
  "by_method": {"ru_iupac": 1, "cas": 1, "pubchem": 1, "smiles": 1, "unresolved": 1}
}
```

**Что важно:**

- `method` и `confidence` говорят, кто и насколько уверенно разрешил имя; `translated_from` — через
  какое английское имя прошёл русский запрос.
- Резолвер не всесилен: тривиальное «боргидрид натрия» не разрешилось, а `[Na+].[BH4-]` находится
  сразу. **Где SMILES известен — подавайте SMILES.**
- Строка, которую можно прочесть и как имя, и как SMILES (`CO`, `NO`, `NBS`, `Br`), **не
  угадывается**: в ответе будет отказ с подсказкой, как записать однозначно.
- Пустой список или больше 200 имён — ошибка вызова.

## 8. Инструмент 5 — `estimate_synthesis_cost`

**Зачем.** Главный инструмент: посчитать стоимость набора реагентов.

**Параметры:**

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `reagents` | список | — | позиции `{smiles \| name, qty, unit, purity_min?}` — структура **или** имя, можно смешивать в одном списке |
| `strategy` | строка | `cheapest` | `cheapest` — дешевейшее по каждому реагенту независимо; `single_supplier` — один поставщик на всё |
| `similarity` | строка | `hard` | `hard` — только точные совпадения; `soft` — каскад с подбором похожего |
| `preferred_currency` | строка | `RUB` | валюта предпочтения: `RUB`, `USD`, `EUR` |
| `use_llm` | булево | `false` | разрешить LLM-слой перевода имён (см. `search_by_structure`) |

`unit` — масса или объём: `g`, `kg`, `ml`, `l`. Моли в текущей версии не поддерживаются.

Единица запроса должна быть **той же размерности, что фасовка в прайсе**: дихлорметан, запрошенный
в `ml`, против прайса в `kg` даёт `missing` с `reason: "unit_mismatch"` — это не отсутствие
вещества, а несовместимость единиц. Жидкости надёжнее запрашивать массой.

Имя разрешается в структуру резолвером, и результат виден в поле ответа `resolved_inputs` — какую
именно молекулу посчитали (см. [`resolve_chemicals`](#7-инструмент-4--resolve_chemicals)).
Неразрешённое имя попадает в `missing` с `reason: "unresolved_name"` — до поиска цены дело не доходит.

### Режимы `hard` и `soft` — важное различие

**`hard` (по умолчанию)** — бескомпромиссный: любой реагент без точного совпадения обрывает расчёт.
Частичной сметы не будет. Это защита от тихо неполного ответа: лучше явная ошибка, чем смета,
в которой молча потерялась половина позиций.

```json
{"reagents": [{"smiles": "CCO", "qty": 1, "unit": "kg"}], "similarity": "hard"}
```

```json
{
  "line_items": [],
  "total_by_currency": {},
  "missing": [{"smiles": "CCO", "reason": "no_match", "detail": ""}],
  "comment": "режим hard: нет точного совпадения хотя бы по одному реагенту",
  "error": {"error": "no_exact_match", "unmatched": ["CCO"]}
}
```

**`soft`** — каскад: точное совпадение → по связности → похожее по Tanimoto. Считает то, что смог,
остальное складывает в `missing`. Каждая позиция, найденная неточно, несёт пояснение в `comment`,
а уровень совпадения виден в `match_level`.

Правило выбора простое: **`hard` — когда числу нужно доверять**, `soft` — когда нужна оценка
и вы готовы читать пояснения.

              {"smiles": "O", "qty": 500, "unit": "ml"}],

## 9. Инструмент 6 — `rank_routes_by_cost`

Отвечает на вопрос: **какой из этих маршрутов дешевле синтезировать.** На вход — список маршрутов,
на выход — они же, отсортированные по стоимости закупки исходных веществ.

Маршрут — это упорядоченные шаги в reaction SMILES (`реагенты>агенты>продукты`). Шагов может быть
один, два, четыре и сколько угодно; шаги идут **в порядке выполнения**, и цель маршрута — главный
продукт последнего шага (первый продукт в записи; остальные считаются побочными).

**Параметры:**

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `routes` | список | — | маршруты `{route_id, steps, target_smiles?, target_name?, overrides?}`; `target_*` нужны, только если цель — не главный продукт последнего шага |
| `target_qty` | число | `1` | целевое количество продукта — одинаковое для всех маршрутов |
| `target_unit` | строка | `g` | `g`, `kg`, `mol`, `mmol`. Объём (`ml`, `l`) целью быть не может: без плотности он в моли не переводится |
| `default_yield` | число | `1.0` | выход шага, если у шага не задан свой; 0 < y ≤ 1 |
| `strategy` | строка | `cheapest` | `cheapest` — дешевейшее по каждому реагенту; `single_supplier` — один поставщик на весь маршрут |
| `similarity` | строка | `soft` | `soft` — каскад с подбором похожего; `hard` — только точные совпадения |
| `preferred_currency` | строка | `RUB` | валюта итога и рейтинга: `RUB`, `USD`, `EUR` |
| `rank_by` | строка | `per_unit` | `per_unit` — по себестоимости; `packs` — по чеку за целые упаковки |
| `include_breakdown` | булево | `true` | вкладывать ли полную смету каждого маршрута (`estimate`) |
| `use_llm` | булево | `false` | разрешить LLM-слой перевода имён; на маршрут из чистых SMILES не влияет |

### Три формы записи шага

Формы можно смешивать в одном маршруте.

**1. Структурная** — reaction SMILES строкой, либо объектом `{"reaction": …, "yield": 0.75}`,
если у шага свой выход:

```json
"CC(=O)Cl.CCO>>CCOC(C)=O"
{"reaction": "Cc1ccccc1.OO>>O=Cc1ccccc1", "yield": 0.75}
```

**2. Именная** — для маршрута, добытого из статьи, где SMILES нет:

```json
{"reactants": ["2,6-ди-трет-бутилфенол", "ацетилхлорид"],
 "agents": ["AlCl3", "CCl4"],
 "products": ["1-(3,5-ди-трет-бутил-4-гидроксифенил)этан-1-он"],
 "conditions": "0–5 °C", "yield": 0.75}
```

Вещество здесь — строка (`"ацетилхлорид"`), либо `{"name": …}`, либо `{"smiles": …}`, либо
`{"name": …, "equiv": 2}` для эквивалентов (то же, что записать вещество дважды в reaction SMILES),
либо `{"name": "CCl4", "amount": {"qty": 50, "unit": "ml"}}`, чтобы растворитель попал в смету.
Явный тип (`name` / `smiles`) побеждает всегда: `CO` как имя — оксид углерода, как SMILES — метанол;
голую строку такого вида классификатор не угадывает, а отказывает. `"@prev"` в реагентах — продукт
предыдущей стадии. Поле `conditions` принимается, но на расчёт не влияет.

**3. Строковая** — стадия одной строкой:

```json
{"text": "+ Br2 в EtOH → 2-бром-1-(...)этан-1-он, выход 65%"}
```

Стрелка делит стадию, `+` соединяет реагенты, запятая с пробелом отделяет агенты и условия;
условия (`0–5 °C`, `2 ч`) распознаются по виду и в реагенты не попадают. Ведущий `+` значит
«к продукту предыдущей стадии».

**Имена превращаются в структуры, и подстановка видна.** Собранные reaction SMILES, которые реально
пошли в расчёт, возвращаются в `routes[].steps_smiles`; что во что превратилось, каким слоем, с какой
массой и формулой — в `routes[].resolved_inputs`. Имя, которое не разрешилось, делает маршрут
`invalid` с объяснением: без структуры нет ни молярной массы, ни цены.

Обратите внимание: `similarity` здесь по умолчанию `soft`, а не `hard`, как в
`estimate_synthesis_cost`. Маршрут почти всегда содержит вещество, которого нет в прайсах,
и жёсткий режим отбрасывал бы его целиком.

```json
{
  "routes": [
    { "route_id": "перманганат",
      "steps": ["Cc1ccccc1.([K+].[O-][Mn](=O)(=O)=O).([K+].[O-][Mn](=O)(=O)=O)>>OC(=O)c1ccccc1"] },
    { "route_id": "через-бензальдегид",
      "steps": [
        { "reaction": "Cc1ccccc1.OO>>O=Cc1ccccc1",      "yield": 0.75 },
        { "reaction": "O=Cc1ccccc1.OO>>OC(=O)c1ccccc1", "yield": 0.75 }
      ] }
  ],
  "target_qty": 100,
  "target_unit": "g",
  "default_yield": 0.75
}
```

### Что именно считается

**Покупаются только стартовые материалы.** Бензальдегид во втором маршруте не покупается: он
получается на первом шаге. Он попадёт в `intermediates`, а не в смету — иначе длинный маршрут
проигрывал бы просто из-за числа строк. Сам целевой продукт в `intermediates` не входит: он
результат маршрута и лежит в отдельном поле `target_smiles` — там же видно, что именно сервис
счёл целью, если вы её явно не задавали.

**Количества выводятся обратным ходом от цели.** 100 г бензойной кислоты → моли → делим на выход
шага → моли реагентов по стехиометрии → граммы по молярной массе. Потери накапливаются по цепочке:
три шага по 50% требуют восьмикратного избытка исходного вещества. Все маршруты считаются на одно
и то же `target_qty` — иначе сравнивать нечего.

**Стехиометрия берётся из самой записи:** повтор компонента — это эквивалент. Два перманганата в
примере выше означают 2 экв. окислителя. Если эквиваленты не проставлены, каждый реагент берётся
как 1 экв.

**`default_yield` по умолчанию равен 1.0** — то есть потери НЕ моделируются и расход реагентов
занижен. Это осознанный отказ выдумывать за химика: поставьте реальные выходы (`yield` у шага или
`default_yield` на весь расчёт), иначе сравнение маршрутов разной длины будет к ним слишком добрым.
Ответ всегда напоминает об этом в `assumptions`.

### Две вещи, о которые легко споткнуться

**Соли нужно писать в скобках.** В reaction SMILES точка разделяет компоненты, поэтому
`[K+].[O-][Mn](=O)(=O)=O` — это два вещества (ион калия и перманганат-ион), которых в прайсе нет,
а `([K+].[O-][Mn](=O)(=O)=O)` — одно, перманганат калия, который найдётся.

**Агенты не стоят денег в этом расчёте.** Всё, что стоит между двумя `>` (растворитель, катализатор,
среда), стехиометрии не имеет: сколько дихлорметана уйдёт на реакцию, из уравнения не следует. Такие
вещества перечисляются в `unpriced_agents`. Чтобы учесть их стоимость, задайте количество явно:

```json
{ "route_id": "дихромат",
  "steps": ["Cc1ccccc1.([K+].[K+].[O-][Cr](=O)(=O)O[Cr](=O)(=O)[O-])>OS(=O)(=O)O>OC(=O)c1ccccc1"],
  "overrides": [ { "smiles": "OS(=O)(=O)O", "qty": 200, "unit": "g" } ] }
```

`overrides` перекрывает и стехиометрический расчёт: если реагент берут в большом избытке или,
наоборот, регенерируют, задайте его количество руками. В именной записи то же делает `amount`
прямо у вещества — тогда растворитель не приходится называть дважды. Сопоставление override с
веществом маршрута идёт по InChIKey, поэтому его можно задать и именем.

Агент, которому вы задали количество, из `unpriced_agents` уходит и появляется в смете со
`source: "override"` — список показывает только то, что действительно осталось неоплаченным.

### Как читать ответ

У каждого маршрута — статус:

| `status` | Что это значит |
|---|---|
| `ranked` | все исходные вещества оценены, сумма полная |
| `partial` | часть позиций не сопоставлена или осталась «ценой по запросу» — сумма **занижена**, это нижняя граница; подробности в `missing` и `warnings` |
| `unpriceable` | не удалось оценить ничего: сумм нет вовсе (`cost_*` и `currency` равны `null`), маршрут остаётся в ответе с причиной, но без места в рейтинге. Предупреждение здесь говорит «оценить не удалось: N позиц. не сопоставлено» — про занижение речи не идёт, занижать нечего |
| `invalid` | маршрут не разобран: битый SMILES, неразрешённое имя, цель не производится ни одним шагом, объёмная единица цели |

В режиме `similarity: "hard"` любая непокрытая позиция делает маршрут `unpriceable` целиком:
частичная смета в этом режиме не строится, и предупреждение об этом говорит прямо. Если нужна
оценка «по тому, что нашлось», берите `soft` (он и стоит по умолчанию в этом инструменте).

Потребность считается даже тогда, когда цен нет ни на что: `starting_materials` покажет, что и в
каком количестве пришлось бы купить, — по этому списку удобно понять, чего не хватает базе.

Место в рейтинге (`rank`, 1 — дешевейший) получают только маршруты с суммой. Сортировка идёт
**внутри одной валюты** — курсов в сервисе нет, поэтому маршрут, посчитанный не в предпочтённой
валюте, встаёт после неё с пояснением в `warnings`.

`rank_by` выбирает, по какому числу строить рейтинг: `per_unit` (себестоимость, по умолчанию —
честное сравнение химии) или `packs` (реальный чек за целые упаковки; при малых количествах он
скорее сравнивает фасовки поставщиков, чем маршруты).

`starting_materials` показывает, откуда взялось каждое количество: `moles`, `molar_mass`, номера
шагов и `source` — `stoichiometry` или `override`. Полная смета маршрута лежит в `estimate`
(её можно отключить через `include_breakdown: false`, если нужен только рейтинг).

Суммы маршрута округлены до копейки, молярные массы — до миллиграмма на моль. Более дробные
числа означали бы точность, которой нет ни в прайсе, ни в стехиометрии.

## 10. Как читать смету

### Два числа стоимости — и они не должны совпадать

Это главное, что нужно понять про ответ расчёта.

- **`cost_packs` — реальный чек.** Упаковки целые: нужно 2 кг, а глицерин продаётся по 12 кг —
  значит покупаете одну упаковку за 5 664 ₽ и получаете 12 кг.
- **`cost_per_unit` — себестоимость.** Сколько стоят именно те 2 кг, что вам нужны: 944 ₽.

Разрыв между числами (5 664 против 944) — не ошибка, а честная картина: **вы платите за упаковку,
а расходуете часть**. Для закупки смотрите на первое число, для калькуляции себестоимости — на второе.
Итоги в `total_by_currency` содержат оба.

### `missing` читать обязательно

`missing` перечисляет реагенты, для которых предложение не найдено. В режиме `soft` смета
считается **без них**, поэтому итог заведомо неполон. Причины:

| `reason` | Что произошло |
|---|---|
| `no_match` | ни точного, ни похожего соединения не нашлось |
| `invalid_smiles` | входной SMILES не разобрался |
| `unit_mismatch` | единицы несовместимы (запрос в `ml`, а фасовка в `kg`; запрос в граммах, а фасовка в штуках) |
| `unresolved_name` | имя не удалось превратить в структуру; до поиска цены дело не дошло |

### Валюты не складываются

`total_by_currency` — словарь: отдельный итог на каждую валюту. Пересчёта по курсу **нет и не будет**:
курс — внешнее допущение, и зашивать его в расчёт себестоимости неправильно. Если у поставщика цена
в долларах, вы увидите отдельную строку `USD`.

Параметр `preferred_currency` управляет выбором: среди предложений в этой валюте берётся дешевейшее.
Если в предпочтённой валюте предложений нет, берётся дешевейшее в другой, и строка сметы поясняет это.

### Признаки, требующие внимания

| Поле | Значение | Что делать |
|---|---|---|
| `is_bulk: true` | фасовка не указана, «цена по запросу» | числа в строке справочные, в итог не входят |
| `bulk_excluded_count > 0` | столько позиций осталось за пределами сумм | итог неполон ровно на них |
| `basis_suspect: true` | базис цены поставщика признан ненадёжным | предложение выбрано за неимением альтернатив, проверьте вручную |
| `match_level: "по_связности"` | нашлась другая солевая/стереоформа | обычно приемлемо, но проверьте |
| `match_level: "похожее"` | подобрано по Tanimoto | **это другое вещество**, читайте `comment` |

Блок `assumptions` присутствует всегда и перечисляет допущения, на которых построен ответ.

## 11. Рецепты

**Сколько стоит килограмм вещества у самого дешёвого поставщика**

`estimate_synthesis_cost` с одной позицией, `similarity: "hard"`, `strategy: "cheapest"`.
Смотрите `cost_per_unit`.

**Собрать всё у одного поставщика**

`strategy: "single_supplier"` — выбирается поставщик с минимальной суммарной себестоимостью
по всем позициям сразу. Полезно, когда доставка и документооборот дороже разницы в цене.

**Проверить, есть ли вещество в базе вообще**

`search_by_structure` в режиме `exact`. Пустой ответ означает, что структура не сопоставлена —
но вещество может присутствовать в прайсе под нераспознанным названием. Проверьте
`search_reagents_by_name` по русскому названию.

**Найти вещество, когда точное название неизвестно**

`search_reagents_by_name` с приблизительным написанием, затем `get_price` по найденному
`name_norm` — увидите все фасовки и поставщиков.

**Сравнить несколько путей синтеза одного вещества**

`rank_routes_by_cost` со списком маршрутов и общим `target_qty`. Проставьте реальные выходы
(`yield` у шага) — без них длинные маршруты выглядят дешевле, чем есть. Читайте `status` перед
ценой: маршрут с непокрытыми реагентами может встать выше просто потому, что часть его стоимости
не посчитана.

**Оценить один маршрут, ни с чем не сравнивая**

Тот же инструмент со списком из одного маршрута. Полезны `starting_materials` (что и сколько
закупать) и `estimate` (у кого и по какой цене).

**Понять, каких реагентов маршрута нет в базе**

Запустите маршрут и посмотрите `missing` вместе со `starting_materials`: потребность считается
даже для веществ без единого предложения, поэтому список сразу показывает, что искать вручную
через `search_reagents_by_name`.

**Сравнить фасовки одного реактива**

`get_price` с фильтром `pack_unit`. Ответ отсортирован по `unit_price`, поэтому оптовая
лестница видна сразу.

## 12. Ограничения и подводные камни

**Покрытие структурой неполное — и это главное ограничение.** Поиск по SMILES видит только те
предложения, чьи названия удалось превратить в молекулу. Прайсы русские, а внешние химические базы
русских названий не понимают, поэтому распознавание идёт через перевод и справочники, и часть
позиций остаётся нераспознанной. Практический вывод: **пустой ответ структурного поиска не означает,
что вещества нет в продаже.** Перепроверяйте поиском по названию.

**Часть позиций не имеет структуры в принципе.** Смеси, технические продукты, стандартные образцы
(ГСО), пасты, растворители-композиции — у них нет одной молекулы. Для них правильный ответ сервиса —
честное отсутствие структуры, а не выдуманное соединение.

**Цены — из прайс-листов, а не из живых остатков.** Сервис не знает о наличии на складе, о скидках,
о сроках поставки и о том, актуален ли прайс сегодня. Поле `price_list_date` показывает дату прайса,
если поставщик её указал.

**Учитывайте НДС на своей стороне.** Прайсы разных поставщиков могут быть с НДС и без; сервис
приводит цены к сопоставимому виду по базису (за упаковку / за единицу), но налоговую составляющую
не нормализует.

**Поиск по названию — нечёткий.** Он вернёт похожие строки, включая другие вещества («Глицин»
по запросу «глицерин»). Для однозначности используйте структурный поиск — или задайте `name` в
`search_by_structure` / `estimate_synthesis_cost`: там имя сначала разрешается в молекулу, и поиск
идёт по InChIKey, а не по буквам.

**Разрешение имён — не гарантировано.** Каскад словарь → OPSIN → PubChem → CIR покрывает
систематику и распространённые тривиальные имена, но не всё (см. «боргидрид натрия» в
[`resolve_chemicals`](#7-инструмент-4--resolve_chemicals)). Где SMILES известен — подавайте SMILES;
подстановку всегда проверяйте по `resolved_inputs`.

**`unit_price` — за единицу фасовки, не за грамм.** Цена приведена к `pack_unit` (`kg`, `g`, `l`,
`ml`); для руб/г при `kg` делите на 1000, а для объёмных единиц нужна плотность, которой сервис
не знает.

**Моли не поддерживаются в `estimate_synthesis_cost`.** Только масса и объём: `g`, `kg`, `ml`, `l`.
Пересчёт через молярную массу делайте на своей стороне (`resolve_chemicals` даёт `molar_mass`);
в `rank_routes_by_cost` цель можно задать в `mol` / `mmol`.

**Валюты не конвертируются.** Итоги приходят раздельно по валютам; курс применяйте сами, если нужен.

**Сессии живут в памяти сервиса.** Сервер работает в одном экземпляре, и при его перезапуске
активные MCP-сессии обрываются — клиент должен уметь переинициализироваться.
