S3 Vault: новая поверхность инструментов

Что изменилось в работе с файлами в CoScientist и что нужно знать каждому. Сентябрь 2026.

Зачем это сделано

  • Файлы прогонов больше не теряются: артефакты переживают завершение пайплайна и перезапуск.
  • Бакет больше не разрастается без контроля: временные файлы удаляются автоматически.
  • Все серверы и агенты передают файлы одинаково — один контракт, один формат ключей.
  • Каждый шаг пайплайна фиксирует входные и выходные файлы в графе исполнения.

Главное изменение: две поверхности инструментов

Vault-сервер предоставляет два набора инструментов. Агенты видят только рабочую поверхность. Операции жизненного цикла остаются на стороне фреймворка.

Поверхность Инструменты Кто вызывает
worker get_upload_link, get_download_link Агенты (CoderAgent, DatasetCollectorAgent)
framework promote_artifact, cleanup_session, update_artifact_metadata, get_session_manifest, list_artifacts Только код фреймворка. Агенты этих инструментов не видят.
Разделение выполняется на клиенте через tool_filter в ADK. Работает один экземпляр сервера (VAULT_SURFACE=all).

Структура ключей и время жизни

<retention>/<user_id>/<session_id>/<feature>/<filename>

ephemeral/alice/session-1/figures/plot.png
permanent/alice/session-1/figures/plot.png
  • ephemeral/ — рабочие файлы. Правило жизненного цикла бакета удаляет их через EPHEMERAL_TTL_DAYS (по умолчанию 7 дней).
  • permanent/ — результаты. Хранятся бессрочно. Открыты на чтение без подписи.
  • Сервер строит каждый ключ сам. Вызывающая сторона не составляет ключи и не выбирает бакет.
  • Агент всегда пишет в ephemeral/. Фреймворк продвигает результаты в permanent/ на финализации отчёта.

Единый контракт ответа

Каждый инструмент, который работает с объектом, возвращает JSON одного вида:

{
  "bucket": "agent-vault",
  "s3_key": "ephemeral/alice/session-1/figures/plot.png",
  "presigned_url": "http://...",
  "expires_in": 604799
}
  • bucket + s3_key — постоянная ссылка. Храните только её.
  • presigned_url — временная ссылка для скачивания. Её срок жизни равен оставшемуся сроку жизни объекта. Никогда не сохраняйте её в граф или отчёт.
  • Для объектов permanent/ ссылка обычная, без подписи и без срока (expires_in: null).

Что это значит для вас

Разработчики MCP-серверов

  • Возвращайте контракт bucket + s3_key + presigned_url из каждого инструмента, который сохраняет файл.
  • Принимайте user_id и session_id параметрами. Плагин подставит их, если оставить пустыми.
  • Пишите объекты только под ephemeral/<user_id>/<session_id>/.
  • Конфигурация — только S3__ENDPOINT_URL, S3__ACCESS_KEY, S3__SECRET_KEY, S3__BUCKET_NAME. Старые имена переменных отзовут через один релиз.

Разработчики агентов

  • Менять ничего не нужно. Агент получает get_upload_link и get_download_link.
  • Загрузка — обычный HTTP PUT по ссылке, без дополнительных заголовков.

Эксплуатация

  • Новая переменная: MCP__VAULT_URL=http://localhost:7338/mcp.
  • Отдельный бакет agent-vault с правилом жизненного цикла на ephemeral/ и анонимным чтением permanent/.
  • EPHEMERAL_TTL_DAYS в .env обязан совпадать с числом дней в правиле бакета.
  • Откат: убрать MCP__VAULT_URL и перезапустить сервис. Прогоны продолжат работать как раньше.
Граница безопасности. Скоупинг ключей — это изоляция от коллизий, а не авторизация между пользователями. Все компоненты по-прежнему делят одни учётные данные бакета. Префикс permanent/ открыт на чтение всем, кто видит MinIO.

Что видно в графе и отчётах

  • Узлы графа исполнения получили поля input_files и output_files со ссылками вида s3://bucket/key. Подписанные URL в граф не попадают.
  • Индекс артефактов сессии хранится на диске: graph_runs/sessions/<user>/<session>/artifacts.json. Перезапуск процесса больше не теряет список файлов.
  • MANIFEST.json отчёта содержит карту promoted: какие объекты продвинуты в permanent/ и под какими ключами.
